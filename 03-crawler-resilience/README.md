# Resilient Community Crawler — 개편 내성 추출 패턴

수십 개 커뮤니티 사이트를 수집하는 크롤러를 운영·유지보수하면서, **사이트 개편과 봇 차단으로 반복되던 수집 장애를 구조적으로 줄인** 설계 패턴을 정리한 저장소입니다.

> ⚠️ 이 코드는 실제 업무에서 사용한 사내 크롤러 엔진 소스가 아닙니다.
> 업무 중 적용한 **문제 해결 방식과 설계 아이디어만** 범용 코드로 새로 재구성한 예시이며,
> 크롤링 대상 사이트명·발주처·내부 시스템 정보는 모두 익명화했습니다.

---

## 해결한 문제

운영 중 가장 잦았던 세 가지 장애 유형입니다.

1. **사이트 개편으로 셀렉터가 깨짐** — HTML 구조·클래스명이 바뀌면 수집이 통째로 실패.
2. **SPA 전환 후 해시 클래스 불안정** — 일부 사이트가 SvelteKit/shadcn 등으로 개편되며 빌드마다 `svelte-a1b2c3` 같은 해시 클래스를 새로 생성. 클래스 기반 셀렉터를 신뢰할 수 없게 됨.
3. **사이트마다 제각각인 데이터 표기** — 오전/오후·AM/PM 혼용, ISO 8601, 타임존, 조회수 콤마 등.

## 핵심 아이디어: 다단계 폴백(fallback) 추출

하나의 셀렉터에 의존하지 않고, **값마다 신뢰도 순으로 여러 전략을 세워** 앞 전략이 실패하면 다음으로 자동 폴백합니다. 우선순위는 마크업 변경에 강한 것부터입니다.

| 순위 | 전략 | 이유 |
|---|---|---|
| 1 | JSON-LD (`application/ld+json`) | 구조화 데이터라 화면 클래스가 바뀌어도 유지됨 |
| 2 | OpenGraph / 표준 `meta` 태그 | 대부분의 사이트가 공통 보유 |
| 3 | 안정적 시맨틱 셀렉터 (`data-*`, id 접미사) | 빌드에 의존하지 않는 요소 |
| 4 | 정규식 기반 텍스트 추출 | 최후의 수단 |

**빌드마다 바뀌는 해시 클래스는 셀렉터에 절대 쓰지 않는다** — 이 원칙 하나로 SPA 개편 시 재발하던 장애를 크게 줄였습니다.

## 적용한 세부 기법

- **본문 셀렉터의 접미사 매칭** — 게시판별로 `economy-post-content`, `free-post-content`처럼 접두어가 달라도 `id$=post-content`(접미사 매칭)로 한 번에 대응.
- **공용 슬롯의 우선순위 강등** — shadcn `data-slot=card-content`는 댓글 카드 등과 겹칠 수 있어, 더 구체적인 본문 셀렉터 뒤로 순위를 낮춤.
- **집계 필드만 신뢰** — JSON-LD의 `comment[]` 배열은 앞 몇 개만 잘려 담기는 경우가 있어, 댓글수는 `interactionStatistic(CommentAction)` 집계값만 사용.
- **로케일 차이 대응** — 크롤러 요청이 영문 로케일로 렌더되어 날짜가 `AM/PM`으로 오는 케이스까지 파싱.
- **URL 라우팅 레지스트리** — 목록/게시글 URL 판별 정규식을 사이트별로 모아 관리. 게시판 추가 = 규칙 한 줄 추가(예: `pt` → `(pt|name)`). 게시글 URL의 꼬리 파라미터를 제거해 중복 수집 방지.
- **외부 소스 장애 시 대체 경로 전환(failover)** — 특정 지표를 단일 외부 수집기에 의존하던 구조에서, 장애 발생 시 대체 수집 소스로 전환하고 템플릿을 조정해 수집을 재개.

## 구성

```
src_python/
  resilient_extractor.py   # 다단계 폴백 추출기 (requests + BeautifulSoup 가정)
  url_router.py            # 목록/게시글 URL 판별 레지스트리 + URL 정규화
src_js/
  resilient_extractor.js   # 동일 로직의 jsoup 스타일 버전 (원본 엔진 환경에 가까움)
docs/
  크롤러_유지보수_트러블슈팅.md   # 사례별 상세 설명(문제→분석→해결→결과)
```

## 실행

```bash
# Python
pip install beautifulsoup4
python src_python/resilient_extractor.py   # 합성 HTML 로 동작 시연
python src_python/url_router.py            # URL 분류/정규화 시연
```

두 스크립트 모두 외부 네트워크 없이 내장 예시 데이터로 동작합니다.

## 이 작업에서 보여주고자 한 역량

- 운영 중 반복 장애를 **개별 수정이 아닌 구조 개선**으로 해결
- 외부 시스템(사이트) 변화에 견디는 **방어적 설계**
- 지저분한 실데이터를 **일관 포맷으로 정규화**하는 처리력
- 유지보수 비용을 낮추는 **설정 중심(레지스트리) 구조화**
